FEATURE PLAN: PULL DEFECTS FROM COVERITY SERVER
================================================================================
Date: 2026-08-14

PROBLEM BEING SOLVED
--------------------
When exporting a Coverity report as CSV from the Coverity Connect web UI, the
"Line" column often shows "Various" for many defects. This makes it impossible
for the analysis tool to locate the defect in source code, extract the
enclosing function, or run meaningful heuristic analysis.

SOLUTION
--------
Add a "Pull from Coverity" feature that connects directly to the Coverity
Connect server via SOAP v9 API, fetches defects with their real line numbers
and event traces, saves the result as a structured Excel file locally, and
auto-loads it into the analysis pipeline — bypassing the broken CSV export
entirely.

CHANGE 1B — Add get_defect_events(cid_list, stream_name) method
---------------------------------------------------------------
New method placed after get_defects_for_project().

Purpose: fetch the per-defect Coverity event trace (the step-by-step
execution path that Coverity recorded when it detected the defect).

SOAP call used:
  client.service.getStreamDefects(
      mergedDefectIdDataObjs = [{"cid": c, "mergeKey": ""} for c in batch],
      streamId               = {"name": stream_name}
  )

Input:
  cid_list    — list of int CIDs (processed in batches of 50)
  stream_name — Coverity stream name string

SOAP response structure:
  response.streamDefects[]
    .cid
    .defectInstances[0]
      .events[]
        .eventNumber      → step  (int)
        .eventTag         → type  (e.g. "overrun_static", "condition")
        .eventDescription → description (human-readable text)
        .lineNumber       → line  (int)
        .filePathname     → file  (str, may be empty)

Return value:
  dict[cid (int) → list of event dicts]
  Each event dict: {"step": int, "type": str, "description": str,
                    "file": str, "line": int}

Error handling:
  Entire method wrapped in try/except.
  If server does not support getStreamDefects (older Coverity versions,
  restricted config), return {} silently — caller treats missing events
  as empty list. Analysis engine already handles events=[] gracefully.

Batching:
  Process 50 CIDs per SOAP call to avoid server timeouts.


CHANGE 1C — Add get_defects_with_events(stream_name, max_defects, progress_cb) method
--------------------------------------------------------------------------------------
Orchestrator method that combines defect fetch + event fetch.
Placed after get_defect_events().

Algorithm:
  Step 1: call existing get_defects_for_stream(stream_name, max_defects)
          → returns list of defect dicts (cid, checker, file, line, function,
            type, severity)

  Step 2: collect all CIDs from step 1
          loop in batches of 50:
            call get_defect_events(batch, stream_name)
            merge results into events_map dict
            call progress_cb(done, total) if provided
              (used by UI progress bar)

  Step 3: attach events to each defect dict:
            d["events"] = events_map.get(d["cid"], [])

  Step 4: return (defects_list, None) on success
          return ([], error_string) on failure

Signature:
  def get_defects_with_events(self, stream_name, max_defects=5000,
                               progress_cb=None):
      ...
      Returns (list_of_dicts, error_or_None)

CHANGE 2A — Add write_pull_excel(defects, output_path) function
---------------------------------------------------------------
Location: immediately after parse_coverity_excel() function (after line ~420).

Purpose: write a structured .xlsx file from the SOAP-pulled defect list.
The columns are chosen to exactly match what parse_coverity_excel()'s fuzzy
column matcher already understands — so no parser changes are needed.

COLUMNS WRITTEN:

  Col A  header="CID"            source: d["cid"]       (int)
  Col B  header="Checker"        source: d["checker"]   (str)
  Col C  header="Subcategory"    source: d["type"]      (str, checker sub-type)
  Col D  header="Severity"       source: d["severity"]  (str: High/Medium/Low)
  Col E  header="File"           source: d["file"]      (str, relative path)
  Col F  header="Line"           source: d["line"]      (int, ALWAYS integer —
                                                          this is the core fix,
                                                          never "Various")
  Col G  header="Function"       source: d["function"]  (str)
  Col H  header="Events Summary" source: d["events"]    (formatted string)

Events Summary format (same as coverity_gui_excel.py already uses):
  "tag@file:line — description; tag@file:line — description; ..."
  If events list is empty: write "" (empty string)

EXCEL STYLING (openpyxl, same style as existing exports):
  Header row:
    Fill color : 1F4E79  (dark navy blue)
    Font       : white, bold, size 10
    Alignment  : centered, wrap_text=True
    Row height : 22pt

  Column widths:
    A (CID)            : 8
    B (Checker)        : 22
    C (Subcategory)    : 25
    D (Severity)       : 12
    E (File)           : 45
    F (Line)           : 7
    G (Function)       : 30
    H (Events Summary) : 60

  Data rows:
    Plain white background (no colour coding — tool adds colours after analysis)
    Vertical alignment: top
    wrap_text: True for Events Summary column only

Return value: None
On failure  : raise exception (caller catches and logs it)

--- THREADING MODEL ---

Uses a dialog-local queue (self._q = queue.Queue()).
Same pattern as AnalysisPage:

  _pull()        — main thread: disables button, starts thread, starts polling
  _pull_worker() — background thread: calls SOAP, writes Excel, posts to queue
  _poll_queue()  — main thread: reads queue every 50ms via self.after()

Queue message types posted by _pull_worker():
  ("info",  text)          — log a white info line
  ("ok",    text)          — log a green success line
  ("warn",  text)          — log a yellow warning line
  ("error", text)          — log a red error line
  ("tick",  pct, text)     — update progress bar to pct (0-100) + log text
  ("done",  path_or_None)  — signal completion; path=None means failure

_pull_worker() sequence:
  1. Post ("info", "Connecting to stream <name>…")
  2. Call client.get_defects_with_events(stream, limit, progress_cb)
       progress_cb posts ("tick", pct, "Fetching events… done/total")
  3. If error: post ("error", msg) + ("done", None), return
  4. Post ("info", "Fetched N defects. Writing Excel…")
  5. Call write_pull_excel(defects, out_path)
  6. If exception: post ("error", str(e)) + ("done", None), return
  7. Post ("ok", "Saved: <path>")
  8. Post ("done", out_path)

_on_pull_done(path) called when ("done", ...) received:
  If path is None:
    re-enable Pull button, leave dialog open
  If path is not None:
    self.result_excel_path = path
    show messagebox.showinfo("Pull Complete",
        "Defects saved to:\n<path>\n\nThe report path has been filled in.")
    self.destroy()

================================================================================
DESIGN DECISIONS
================================================================================

Events fetch is BEST-EFFORT
  If the Coverity server does not support getStreamDefects (older versions
  or restricted permissions), the events column is left empty. The analysis
  engine already handles events=[] by falling back to heuristic analysis.
  This is intentional — pull still works for line numbers even without events.

No changes to parse_coverity_excel()
  The Excel columns written by write_pull_excel() are named to match the
  fuzzy column matcher already in parse_coverity_excel(). Zero parser changes
  needed.

Credentials not persisted to disk
  Security decision. User retypes credentials each session.
  No keychain or config file storage.

"All streams in project" aggregation
  When user selects "— All streams in project —", the tool calls
  get_defects_for_project() which already aggregates across all streams
  (deduplicating by CID). Events are fetched per stream using the first
  stream that listed the defect.

No disposition push in this dialog
  Push is already handled by PushDialog (accessible from the main header).
  PullDialog is read-only from the server's perspective.

SOAP only (no REST/Black Duck API)
  Matches the existing coverity_soap_client.py architecture. The tool
  already has zeep installed for SOAP; no new HTTP client needed.

================================================================================
SCOPE EXCLUDED FROM THIS FEATURE
================================================================================

  - No write-back of dispositions (that is PushDialog's job)
  - No Black Duck REST API integration
  - No credential storage / keychain
  - No "Pull all projects" batch mode
  - No scheduling / automated pull on timer
  - No delta pull (only changed defects since last pull)
